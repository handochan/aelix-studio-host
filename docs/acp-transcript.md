# ACP transcript synchronization

The Host commits a completed transcript v1 projection before runtime preparation returns. Studio can fetch the message page after a successful runtime ensure. App-owned messages remain in the active history and the Host archives display rows superseded by the native projection. Replayed frames stay off the live stream. The first successful load of an eligible conversation can change assistant chunking, formatted input echoes, image placeholders, tool output formatting, and the display of cancelled turns or abandoned branches. The adapter provides native order. The Host assigns display timestamps for pagination and preserves existing cursors on appends. Live writes use the same display order. Conversation recency uses wall-clock activity time. [ACP transcript v1 contract](https://github.com/handochan/aelix-acp/blob/7b4853863c4e4a3674aba56ae8670c79b3b9bcc1/docs/studio-integration.md#transcript-synchronization-acp-22-host-4)

A completed v1 load requires coordinates for every display frame. When the adapter supplies `totalFrames`, the Host verifies the count before writing the snapshot. Older adapters can omit the count. The Host still verifies the number of native entries and contiguous parts.

The adapter must advertise v1 during initialization and the session must report the native capability. The Host applies only a complete, successful snapshot. A missing success marker, a failed read, or a recovered path leaves the prior view intact. The Studio native pin `83714045` uses DB-only rendering. An explicit display reset also keeps that ACP binding and its guarded fork descendants on DB-only rendering.

An unidentified hidden input keeps the conversation on DB-only rendering, including conversations that also contain identified inputs. For a new hidden input, the Host checks the correlated prompt's live user chunks and stored settlement, then records the native key on its existing hidden row. A verified receipt survives a failed or cancelled turn when a native assistant delta or tool execution confirms that the input loop completed. A lone matching receipt on an interrupted input loop could belong to an injected input, so ambiguous, unconfirmed, or rewritten input stays unbound. A verified key keeps the matching replay entry hidden, even when another input contains identical text. [Host #4 hidden-input decision](https://github.com/handochan/aelix-studio-host/issues/4#issuecomment-7163528828)

The transcript projection preserves adapter events by event identity and uses ACP's verified tool associations. The archive retains the original tool metadata and legacy display, including metadata whose association cannot be verified. Display rows and their archive are scoped to the owning conversation. A guarded HEAD fork carries verified hidden entry IDs. A complete child replay binds them to the child's native session.
